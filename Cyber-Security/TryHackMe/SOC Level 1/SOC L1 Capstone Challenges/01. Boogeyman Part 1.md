---

So far, I have identified that the malicious attachment contains a PowerShell command, as revealed through LNK parsing. 
The command contains an encoded payload using Base64 and UTF-16LE (1200) encoding. 

After decoding, the command creates a `Net.WebClient` object and uses `DownloadString()` to retrieve content from `http://files.bpackaging.xyz/update.` 
It then uses `iex` (Invoke-Expression) to execute the downloaded content as PowerShell code.

Next, I am going to begin investigating some powershell logs, and sicne they are written in JSON, i will use the `jq` command to parse them in terminal. I will refer to this cheatsheet below to assist me in exploring the logs.

### JQ Cheatsheet

| Task | Command |
|---|---|
| **Parse all JSON into beautified output** | `cat powershell.json \| jq` |
| **Print all values from a specific field without printing the field name** | `cat powershell.json \| jq '.Field1'` |
| **Print all values from a specific field with the field name** | `cat powershell.json \| jq '{Field1}'` |
| **Print values from multiple fields** | `cat powershell.json \| jq '{Field1, Field2}'` |
| **Sort logs based on their Timestamp** | `cat powershell.json \| jq -s -c 'sort_by(.Timestamp) \| .[]'` |
| **Sort logs based on their Timestamp and print specific field values** | `cat powershell.json \| jq -s -c 'sort_by(.Timestamp) \| .[] \| {Field}'` |

#### What is the pass of the exfiltrated file?

I know that the attacker had executed the binary `sq3.exe` to access a database file named `plum.sqlite` as we established earlier on in the investigation. So I targeted these in my next search.
I found a GET request for the binary that contained encoded data. But I could not resolve it. So i pivoted into searching for any interesting POST requests. I found a good number of POST requests that contained decimal encoding. These decoded to readable text that indicating C2 communication

I found one POST request contained a password, the one in question: `%p9^3!lL^Mz47E2GaT^y`

#### What is the c card number stored inside the exfiltrated file?

It was extremely difficult as I had to refresh my understanding on Tshark commands. But I managed to reconstruct the .kdbx file with 

`tshark -r capture.pcapng -Y 'dns.qry.name contains "bpakcaging.xyz"' -T fields -e dns.qry.name | grep -v '^bpakcaging.xyz$' | grep -E '^[0-9A-Fa-f]+\.bpakcaging\.xyz' | sed 's/\.bpakcaging\.xyz$//' | awk '!seen[$0]++' | tr -d '\n' | xxd -r -p > protected_data.kdbx`
