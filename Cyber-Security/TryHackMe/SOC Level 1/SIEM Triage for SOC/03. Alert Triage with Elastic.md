The alert above tells me that the IP address 203.0.113.55 has made POST requests to the page proxyLogon.ecp -My goal here is to simply use Elastic to visualize the web requests from this IP address.

In Elastic I entered in the search query to highlight all POST requests with the flagged IP
`_index:weblogs and client.ip:203.0.113.55 and http.request.method:POST `
I then began building a table by adding client.ip, user.agent, http.request.method, url.path, and http.response.status_code

<img width="2560" height="822" alt="image" src="https://github.com/user-attachments/assets/8e3e777b-c46c-4594-9a5d-35ed4b482e6e" />

Now I can see the data in a more structured and legible manner. 
Questions:
How many POST requests were made to proxyLogon.ecp by the flagged IP address? 3
Which user.agent paired with the IP address 203.0.113.55 made the POST requests? python-requests/2.25.1

Upon learning more about the user agent and page name I would see the requests are automated and related to the Proxy Logon vulnerability (https://proxylogon.com/). This is a red flag, but let's quickly glance at the next high severity alert.

This alert comes in just 7 minutes after the previous one and concerns the same IP address 203.0.113.55
The trigger filed also contains `cmd=` which is a hallmark paramter of web shell activity. Attackers can append commands to the parameter like `cmd=whoami`

Using Elastic I entered in a search query to search for GET requests and the file errorEE.aspx
`index:weblogs and client.ip:203.0.113.55 and http.request.method:GET and errorEE.aspx`
I then sorted the requests Old-New to show the requests that came in first at the top

<img width="560" height="259" alt="image" src="https://github.com/user-attachments/assets/6e24d2fa-c939-41a8-a596-8bd4c94a9330" />

Looking a the url.path field we can see commands run using the web shell. This would indicate a breach and I would classify both alerts now as a True Positive event and escalate to L2
