## Investigating Web Attacks
ALERT #1

<img width="480" height="204" alt="image" src="https://github.com/user-attachments/assets/d3bccf5e-232e-4068-8927-8843b612d640" />

The alert above tells me that the IP address 203.0.113.55 has made POST requests to the page proxyLogon.ecp -My goal here is to simply use Elastic to visualize the web requests from this IP address.

In Elastic I entered in the search query to highlight all POST requests with the flagged IP
`_index:weblogs and client.ip:203.0.113.55 and http.request.method:POST `
I then began building a table by adding client.ip, user.agent, http.request.method, url.path, and http.response.status_code

<img width="2560" height="822" alt="image" src="https://github.com/user-attachments/assets/8e3e777b-c46c-4594-9a5d-35ed4b482e6e" />

Now I can see the data in a more structured and legible manner. 
Questions:
How many POST requests were made to proxyLogon.ecp by the flagged IP address? 3
Which user.agent paired with the IP address 203.0.113.55 made the POST requests? python-requests/2.25.1

Upon learning more about the user agent and page name I would see the requests are automated and related to the Proxy Logon vulnerability (https://proxylogon.com/). This is a red flag, but let's quickly glance at the next high severity alert.

I then sorted the requests Old-New to show the requests that came in first at the top

## Uncovering Account Activity

I discovered some red flags in the web log previously. But suspicious network traffic is only part of the story. It's now time to pivot into host based evidence to uncover more of the story and determine if the attacker has moved further.

ALERT #3

<img width="481" height="205" alt="image" src="https://github.com/user-attachments/assets/84457523-1eb0-4991-bdf0-dca6507ae46d" />

A new alert has come in and it shows that an Administrator account has accessed the server outside of business hours.
My first move here is to confirm the logon - when it happened, how it happened and from what location?
I'll start my search in Elastic with the event code 4624 against the hostname and Administrator account.

`@timestamp >= "2025-07-20T05:11:22" and winlog.event_id:4624 and host.name:winserv2019.some.corp and winlog.event_data.TargetUserName:Administrator`

And just like before. I will add the following fields so the data is displayed in a more structured and legible way for this investigation.


    winlog.event_id
    host.name
    winlog.event_data.TargetUserName
    winlog.logon.type
    winlog.event_data.IpAddress

<img width="1002" height="272" alt="image" src="https://github.com/user-attachments/assets/3348e0d2-ce26-490f-b909-eb3f1435bf6c" />

I can see now that the suspicious IP address from the previous alerts (203.0.113.55) successfully logged onto the Administrator account on host winserv2019.some.corp

I can also correlate Sysmon logs to validate the Administrator authentication and investigate what happened after. So I will adjust my search query and selected fields to look into Sysmon Event ID: 1 (Process Creation)

`@timestamp >= "2025-07-20T05:11:22" and winlog.event_id:1 and user.name: "Administrator"`

    user.name
    process.parent.name
    process.command_line

<img width="1273" height="934" alt="image" src="https://github.com/user-attachments/assets/ebd61078-6006-46b7-b405-5142b271d283" />

From this I can verify the Administrator logon initiated a process chain that aligns with Windows session initialization. The 2 queries have helped confirm the logon occurred but the evidence I have so far isn't enough to validate any malicious behavior. Perhaps the Administrator started work earlier today. So i will investigate the next alert to see what the Administrator account was up to.
