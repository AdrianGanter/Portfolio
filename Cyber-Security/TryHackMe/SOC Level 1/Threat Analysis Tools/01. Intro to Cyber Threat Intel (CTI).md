# Intro to Cyber Threat Intelligence (CTI)

## Overview

Cyber Threat Intelligence (CTI) provides context to security events, allowing analysts to determine whether an alert is genuinely malicious and how to respond.

For a SOC Level 1 analyst, CTI transforms alert triage from guesswork into informed decision-making by answering:

- **Who** is behind the activity?
- **What** have they done before?
- **How** should the organisation respond?

The goal is not simply to recognise an IP address or file hash, but to understand **why it matters**.

---

# Data vs Information vs Intelligence

| Layer | Definition | Example | Analyst Action |
|--------|------------|----------|----------------|
| **Data** | Raw observable | `45.155.205.3` | Capture the artefact |
| **Information** | Data with context | IP belongs to Hetzner, first seen 2023 | Record attributes |
| **Intelligence** | Analysed information that drives action | IP identified as active BumbleBee C2 | Escalate or block |

## Key Idea

A Level 1 analyst enriches raw artefacts until they become actionable intelligence.

This process is called **enrichment**, using internal, public and commercial intelligence sources.

---

# Core Threat Intelligence Terms

## Indicator of Compromise (IOC)

Evidence that a compromise has already occurred.

Examples:

- Malicious IP address
- Malware hash
- Registry persistence key
- Command & Control (C2) server

---

## Indicator of Attack (IOA)

Evidence that malicious activity is occurring right now.

Examples:

- PowerShell spawning suspicious processes
- Repeated SSH login failures
- Unexpected DNS beaconing

IOAs focus on **behaviour**, not just artefacts.

---

## Tactics, Techniques and Procedures (TTPs)

Describe **how attackers operate**.

Typically referenced using MITRE ATT&CK IDs.

Example:

- `T1110.003` – Password Guessing
- `T1055` – Process Injection

Unlike IOCs, TTPs generally remain effective even if attackers change infrastructure.

# Common Threat Indicators

| Indicator | Examples | Common Enrichment Resources |
|-----------|----------|-----------------------------|
| IP Address | `45.155.205.3` | WHOIS, VirusTotal, Shodan |
| Domain | `malicious-updates[.]net` | WHOIS, SecurityTrails, RiskIQ |

| File Hash | SHA256 / MD5 | VirusTotal, Hybrid Analysis, MalShare |
| Email Address | `billing@evil-corp.com` | MXToolbox, Have I Been Pwned |
| Registry/File Artefacts | `HKCU\Software\Run\updater.exe` | Sigma Rules, EDR searches |

# Threat Intelligence Sources

## Internal Sources

Highest relevance.

Examples:

- SIEM logs
- EDR detections
- Email submissions
- Firewall logs

---

## Commercial Intelligence

Paid vendor services.

Examples:

- Premium threat feeds
- Commercial sandboxes
- Vendor intelligence

Advantages:

- High fidelity
- Frequently updated

Limitations:

- Licensing restrictions
- Export limitations

---

## Open Source Intelligence (OSINT)

Publicly available intelligence.

Examples:

- AbuseIPDB
- URLhaus
- Security blogs
- Academic research

Always validate OSINT before operational use.

---

## Communities & ISACs

Industry information-sharing communities.

Provide:

- Shared indicators
- Threat reports
- Sector-specific intelligence

---

# Threat Intelligence Classifications

## Strategic Intelligence

High-level business intelligence.

Focus:

- Trends
- Threat landscape
- Risk assessment
- Executive decision making

Example:

Annual ransomware trend reports.

---

## Tactical Intelligence

Focuses on attacker behaviour.

Includes:

- TTPs
- MITRE ATT&CK mappings
- Advisory notes

---

## Operational Intelligence

Campaign-specific intelligence.

Answers:

- Who is attacking?
- Why?
- What are they targeting?

Useful for understanding attacker intent.

---

## Technical Intelligence

Atomic indicators.

Examples:

- IP addresses
- Domains
- URLs
- File hashes

This is the intelligence most frequently handled by Level 1 analysts.

---

# Intelligence Feeds vs Platforms

## Threat Feed

Continuous stream of indicators.

Common formats:

- CSV
- STIX
- TAXII

Purpose:

Provides fresh indicators.

Excessive feeds increase false positives.

---

## Threat Intelligence Platform (TIP)

Central repository for intelligence.

Functions:

- Store indicators
- Correlate data
- Manage relationships
- Control sharing permissions

Examples:

- MISP
- OpenCTI

---

# Cyber Threat Intelligence Lifecycle

The CTI lifecycle converts raw data into actionable intelligence.

## 1. Direction

Define intelligence objectives.

Questions include:

- What assets require protection?
- What threats matter?
- What questions need answering?

Example:

- Which IPs target PostgreSQL servers?
- Which malware hashes should be blocked?

---

## 2. Collection

Gather intelligence.

Sources may include:

- Commercial feeds
- OSINT
- MISP
- Vendor reports

Collected data often arrives in:

- STIX
- CSV

---

## 3. Processing

Prepare data for analysis.

Tasks include:

- Standardising formats
- Deduplicating indicators
- Correlating multiple sources
- Assigning metadata
- Applying TLP labels

Output examples:

- Firewall block lists
- YARA rules
- Normalised indicator databases

---

## 4. Analysis

Determine whether intelligence is relevant.

Analysts assess:

- Confidence
- Local sightings
- Multiple-source validation
- False positives

Typical confidence model:

| Confidence | Meaning | Action |
|------------|----------|--------|
| High | Multiple trusted sources + local evidence | Block immediately |
| Medium | Trusted source only | Alert |
| Low | Minimal context | Monitor |

---

## 5. Dissemination

Deliver intelligence to appropriate audiences.

Examples:

| Audience | Format |
|-----------|--------|
| Firewall Team | Block list |
| Endpoint Team | YARA rules |
| Threat Platform | Indicator objects |
| Management | Executive summary |

Tailor information to the audience.

---

## 6. Feedback

Measure effectiveness.

Typical metrics:

- Detection improvements
- False positive rates
- Dwell time
- Missed detections

Results guide improvements for the next CTI cycle.

---

# Traffic Light Protocol (TLP)

Controls how intelligence may be shared.

| Label | Meaning |
|--------|---------|
| **TLP:CLEAR** | Public sharing permitted |
| **TLP:GREEN** | Community sharing only |
| **TLP:AMBER** | Limited sharing on a need-to-know basis |
| **TLP:RED** | Named recipients only |

### Important Rule

When combining indicators with different TLP labels, **the most restrictive label wins**.

Example:

`TLP:CLEAR + TLP:AMBER = TLP:AMBER`

---

# STIX

**Structured Threat Information Expression**

A machine-readable standard for representing cyber threat intelligence.

Used to describe:

- Indicators
- Threat actors
- Malware
- Campaigns
- Relationships

---

# TAXII

**Trusted Automated eXchange of Indicator Information**

Secure API standard used to exchange threat intelligence.

Supports:

- Near real-time sharing
- Detection
- Prevention
- Automated ingestion

Sharing Models:

- **Collection** – Intelligence stored by the producer
- **Channel** – Published to subscribers

---

# MITRE ATT&CK

Knowledge base describing adversary behaviour.

Organises attacks into:

- Tactics
- Techniques
- Procedures (TTPs)

Example:

`T1071.001` – Web Protocol C2

SOC analysts use ATT&CK IDs to:

- Standardise reporting
- Identify attacker behaviour
- Assist escalation
- Map detections

---

# MITRE D3FEND

Defensive counterpart to ATT&CK.

Focuses on:

- Defensive techniques
- Security controls
- Mitigations

Useful for determining **how to defend**, rather than how attackers operate.

---

# Cyber Kill Chain

Describes the stages of an attack.

| Stage | Purpose |
|--------|---------|
| Reconnaissance | Gather information |
| Weaponisation | Build malware/exploit |
| Delivery | Deliver payload |
| Exploitation | Exploit vulnerability |
| Installation | Install malware |
| Command & Control (C2) | Remote control of compromised host |
| Actions on Objectives | Achieve attack goals (exfiltration, ransomware, destruction) |

Understanding the kill chain helps determine:

- Where an attack currently sits
- Where defensive controls should be applied

# Vulnerability Standards

## CVE

**Common Vulnerabilities and Exposures**

Unique identifier for publicly disclosed vulnerabilities.

Example:

`CVE-2023-4863`

---

## CVSS

**Common Vulnerability Scoring System**

Scores vulnerability severity.

Scale:

`0.0 – 10.0`

Factors include:

- Exploitability
- Impact
- Environment

---

## NVD

**National Vulnerability Database**

Maintained database that links:

- CVEs
- CVSS scores
- Affected software
- References
- Exploit information

---

# Threat Intelligence Best Practices

- Enrich indicators before acting.
- Validate OSINT using multiple sources.
- Record the source of every indicator.
- Respect Traffic Light Protocol (TLP) labels.
- Use ATT&CK IDs when documenting attacker behaviour.
- Tailor intelligence to its audience.
- Measure outcomes and continuously improve the CTI lifecycle.

# Exam / Interview Takeaways

- **CTI provides context**, not just indicators.
- **Data → Information → Intelligence** is achieved through enrichment.
- **IOCs** identify evidence of compromise.
- **IOAs** identify malicious behaviour in progress.
- **TTPs** describe attacker methodology and are mapped with MITRE ATT&CK.
- The **CTI Lifecycle** consists of:
  1. Direction
  2. Collection
  3. Processing
  4. Analysis
  5. Dissemination
  6. Feedback
- **Processing** standardises and correlates data.
- **Direction** defines intelligence requirements.
- **STIX** structures threat intelligence.
- **TAXII** transports threat intelligence.
- **ATT&CK** explains attacker behaviour.
- **D3FEND** explains defensive techniques.
- **CVE** identifies vulnerabilities.
- **CVSS** scores severity.
- **NVD** stores vulnerability information.
- The final stage of the Cyber Kill Chain (**Actions on Objectives**) includes activities such as data exfiltration and ransomware deployment.
