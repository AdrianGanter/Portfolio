# IP & Domain Threat Intelligence

## Overview

IP and Domain Threat Intelligence is the process of enriching IP addresses and domains with additional context to determine whether they are legitimate, suspicious, or malicious.

A simple investigation workflow:

> **Verify → Enrich → Decide**

Always use multiple sources before drawing conclusions.

---

# Domain Enrichment

## DNS (Domain Name System)

DNS translates domain names into IP addresses.

### A / AAAA Records
- **A** → IPv4 address
- **AAAA** → IPv6 address

Useful for identifying where a domain is hosted and pivoting to its IP address.

> **Note:** If the IP belongs to a CDN (Cloudflare, CloudFront, Fastly, etc.), investigate the **domain** rather than the shared CDN IP.

---

### TXT Records

TXT records often reveal:

- SPF
- DKIM
- DMARC
- Email providers
- Domain verification records

Missing or unusual records may indicate poor configuration or suspicious infrastructure.

---

### WHOIS / RDAP

Provides domain registration information:

- Registrar
- Registration date
- Expiry date
- Domain age

**Red Flag:** Newly registered domains are commonly associated with phishing and malware campaigns.

---

# Common Domain Attacks

## Typosquatting

Registering domains that closely resemble legitimate ones.

Examples:

- `micros0ft.com`
- `gooogle.com`

Purpose:

- Credential theft
- Malware delivery
- Phishing

---

## IDN (Homograph) Attacks

Uses Unicode characters that visually resemble normal letters.

Example:

Replacing a Latin letter with a Cyrillic equivalent.

Detect using **Punycode**.

Domains beginning with:

`xn--`

contain non-ASCII characters.

# Autonomous Systems (ASN)

An **Autonomous System (AS)** is a network managed by a single organisation.

Each AS has a unique **Autonomous System Number (ASN)**.

| ASN Type | Common Use |
|----------|------------|
| Residential ISP | Home users and consumer devices |
| Hosting Provider | Servers, cloud hosting, malware infrastructure |
| Cloud / CDN | Shared infrastructure requiring further analysis |

Useful lookup tool:

- **BGP.Tools**

---

# Geolocation (GeoIP)

GeoIP estimates the geographic location of an IP address.

Useful for identifying:

- Unexpected login locations
- Unusual network traffic

**Remember:**

- Country-level accuracy is generally reliable.
- City-level accuracy is approximate.
- Geolocation alone is not proof of malicious activity.

---

# Infrastructure Reconnaissance

Useful services for examining exposed infrastructure:

| Tool | Purpose |
|------|---------|
| Shodan | Open ports, services and banners |
| Censys | Internet-facing services and certificates |
| crt.sh | TLS certificate history |

Look for:

- Open management services
- Outdated software
- Self-signed certificates
- Suspicious service banners

---

# VPN, Proxy & Tor Detection

Useful tools:

- IP2Proxy
- Spur

Can identify:

- VPN providers
- Residential proxies
- Tor exit nodes

A VPN or Tor connection can make geolocation unreliable.

---

# Investigation Workflow

1. Examine the domain.
   - Registration age
   - DNS records
   - Reputation
   - Typosquatting or homograph attacks

2. Resolve the domain to an IP.

3. Investigate the IP.
   - Reputation
   - ASN ownership
   - Geolocation
   - VPN / Proxy / Tor usage
   - Exposed services
   - TLS certificates

4. Correlate findings before making a decision.

# Best Practices

- Verify information using multiple sources.
- Investigate newly registered domains carefully.
- Do not judge a domain solely by its reputation score.
- CDN IPs often represent many unrelated websites.
- Use ASN ownership to understand infrastructure.
- Treat geolocation as supporting evidence.
- Check for VPN, proxy or Tor usage.
- Review exposed services and TLS certificates for additional context.
